## Redirect and maturity cautions

Examples of non-equivalent routing include AI Chat Companion → general AI services; multiple chatbot, analytics, and pricing labels → general services; Network → the network directory; FinOps estimator → a consulting page; Status Page → a status route; Referral → an affiliate page. A source label is not proof that an independent product exists at the resolved destination. Zion Project Master ended on insecure HTTP and remains held. Minimal responses were observed for APP-003, APP-052, APP-058, APP-063, APP-077, APP-097, and APP-112.

The directory contains service and partner-program labels alongside apps and planning tools. Do not describe all 115 route records as 115 working applications, open-source projects, or integrated services. Product names mentioning HIPAA, compliance, predictions, security, or automation do not verify those capabilities.

## Maintenance rules

- Retain each stable ID and provenance label when updating a destination.
- Revalidate redirects, page identity, language, HTTPS, and material capability claims before promotion.
- Repair source catalogs through a separately approved website change; this repository does not change the company website.
- Reconcile missing routes and duplicate labels with the catalog owner instead of inventing aliases.
- Preserve historical observations and add a new dated verification snapshot rather than rewriting old evidence.
- Use [Discovery benefits](discovery-benefits.md), [rollout gates](discovery-rollout.md), [questionnaire tracking](commercial-questionnaire.md), and [commercial routing](commercial-routing.md) before making delivery or implementation commitments.
